# 模型与内存占用记录

## Gemma 3 4B（gemma-3-4b-it）
- 命名注意：4B 档位属于 Gemma 3 系列，避免下成 Gemma 2。
- Q4_K_M：权重约 2.49GB，运行内存约 3.0–3.4GB。
- Q3_K_M：权重约 2.10GB，内存占用更低，精度略降。
- Q8_0：权重约 4.13GB，内存压力最大。
- 视觉投影（mmproj）约 851MB；纯文字对话不需要打包。

## Qwen 4B
- 优先获取对应 GGUF 量化版（llama.cpp 链路）；其他框架需格式转换。
- 内存预算与 Gemma 3 4B 同档：4B Q4 权重约 2.5–3GB，运行内存约 3GB 上下。

## 内存约束（Quest 3，8GB 共享内存）
- 模型权重 + KV 缓存 + 应用本体 + 纹理 + STT/TTS 共享同一内存池。
- 上下文长度越长，KV 缓存占用越高；短上下文优先。
- 内存不足时处理顺序：降量化档位 → 缩小上下文 → 减小模型规模 → 切换云端推理。

## 模型外置原则
- 权重、分词器放在头显本地存储，不打入 APK。
- 更换模型只需替换外置权重文件（同一引擎格式前提下）。

## 整机内存预算（Quest 3，8GB 共享内存）

> 当前仓库为代码 / 文档骨架：尚未编译原生 llama.cpp 库，也没有真实 STT / TTS 模型二进制，因此**精确常驻内存必须在真机加载后用 PSS 实测**。下表为预算估算，STT / TTS / 3D 纹理数值为区间估计，不能作为实测结论。

| 组成部分 | 内存性质 | 估算占用 | 依据与不确定性 |
|---|---|---|---|
| 对话 LLM（4B，Q4_K_M） | 常驻 RAM | 3.0–3.4 GB | 权重约 2.49 GB，另含上下文 / KV 缓存；见上文 Gemma 3 4B 记录 |
| KV 缓存 | 随上下文长度增长 | 计入上行；上下文越长占用越高 | 配置 `context_length=2048`；未实测单 token 缓存体积 |
| 离线 STT 模型 | 常驻或按需加载 | 约 0.10–0.30 GB（估算） | 仓库无真实识别模型；占用取决于引擎、量化档位与采样率 |
| 离线 TTS 模型 + 音色 | 常驻或按需加载 | 约 0.15–0.40 GB（估算） | 同上；音色参考数据体积另计 |
| 应用本体 / UI / 对话历史 | RAM（应用堆） | 约 0.20–0.50 GB（估算） | Java/Kotlin 堆、历史文本、提示词缓存；随会话轮次增长 |
| 3D 角色 / 场景纹理 | 共享显存 + RAM | 约 0.30–1.00 GB（估算） | 取决于网格面数、贴图分辨率、压缩格式（ASTC / ETC2） |
| 系统 / 合成器预留 | 不可全部使用 | 系统占用 | 8 GB 为整机总量；系统、XR 合成器与后台进程先占一部分，剩余才给应用 |

### 预算结论
- **活跃内存粗估**：LLM 3.0–3.4 GB + 语音 0.25–0.70 GB + 应用与 3D 0.50–1.50 GB，合计约 **3.8–5.6 GB**；真机需为系统与峰值峰值预留余量。
- **磁盘存储 ≠ 运行内存**：GGUF / STT / TTS 权重先放在闪存上，加载进 RAM 后才占用运行内存；模型文件大小不能直接当作常驻内存。
- **紧张时的降级顺序**：降量化档位（Q4 → Q3）→ 缩短上下文长度 → 减小模型规模（4B → 更小档位）→ STT / TTS 按需加载、用完释放 → 压缩 3D 贴图。

### 真机实测方法
1. 应用运行后执行：`adb shell dumpsys meminfo <包名>`，记录 Total PSS、原生堆、Java 堆、图形缓冲。
2. 切换模型 / 加载语音模型 / 进入场景时分别采样，记录峰值而非平均值。
3. 将实测权重、KV 缓存、STT / TTS、纹理占用回填到本文件；估算区间以真机数据替换。
