# 远端场景生成服务对接：种子入场与 Emma 进入场景

> 目标：另一台服务器负责生成 / 保存场景；Quest 客户端输入种子（seed）后拉取对应场景，并把本地角色（Emma 或替换后的角色）放入场景出生点。场景同步是可选网络扩展；本地对话推理、TTS 离线主链路不依赖该服务器。

## 1. 角色拆分：场景与角色分开加载

| 部分 | 来源 | 说明 | 入库边界 |
|---|---|---|---|
| 场景（mesh、灯光、道具、出生点、环境配置） | 远端服务器按种子生成或检索 | 场景包与清单下载到头显本地缓存 | 场景二进制素材本地私有，不入库 |
| 角色（Emma / 替换角色外观、人设、音色） | 头显本地存储的角色目录 | 入场时加载到场景出生点；人设文本来自角色 profile | 角色素材版权受限，仅本地合法使用；配置骨架可入库 |
| 对话大脑 | 本地 llama.cpp GGUF | 场景加载完成后接入既有推理 + TTS 链路 | 代码 / 文档入库；权重不入库 |

要点：服务器只提供场景，不负责角色模型；角色外观与设定始终在客户端本地管理。

## 2. 完整数据流

```
用户在 Quest 输入 seed
        │
        ▼
客户端构造场景请求（seed、character_id、场景选项、客户端版本）
        │
        ▼
远端场景服务器：按 seed 生成或检索场景包，返回场景清单（manifest）
        │
        ▼
客户端下载场景资源到本地场景缓存（按 scene_id / seed 隔离）
        │
        ▼
校验清单校验和 / 资源哈希；加载本地角色到出生点（spawn point）
        │
        ▼
进入场景对话：本地推理生成回复 → TTS 合成语音 → 气泡与口型动画
```

### 2.1 客户端步骤
1. 读取场景服务开关与服务器地址（`runtime-config.json` 的 `scene` 段；默认关闭，端点留空）。
2. 输入种子后，请求服务器获取场景清单；种子相同应得到可复现的场景配置（服务器侧负责确定性生成或种子缓存）。
3. 清单包含场景资源地址、出生点位置 / 朝向、环境参数、校验和；客户端把资源下载到本地缓存目录。
4. 场景加载完成后，从本地角色目录加载 Emma（或替换角色），放置到清单给出的出生点。
5. 对话回合继续走 `PromptComposer` → `NativeLlamaBridge` → `OfflineTtsBridge` 既有链路。

### 2.2 服务器侧职责（部署在另一台机器，不在本仓库构建）
- 按 seed 生成或检索场景资产；返回可校验的清单。
- 记录 seed → scene_id、资源文件、生成时间；支持相同种子复现。
- 提供静态资源下载地址；可按需做资源压缩与哈希校验。
- 不存储对话记忆；对话历史只留在头显本地。

## 3. 本地目录约定（部署到头显后）

```
/storage/emulated/0/DayDream/
├── scenes/
│   └── <scene-id>/
│       ├── manifest.json          # 场景清单：资源列表、出生点、环境配置、校验和
│       ├── scene-assets/         # 场景网格 / 贴图 / 灯光 / 道具（本地私有，不入库）
│       └── spawn-transform.json   # 角色入场位置与朝向
├── characters/<character-id>/     # 角色人设、外观、音色（本地私有素材 + 可入库骨架）
├── models/  tokenizer/  memory/ voice/
```

## 4. 请求 / 响应清单骨架（示例契约）

### 4.1 请求（客户端 → 服务器）
```json
{
  "seed": "example-seed-0001",
  "character_id": "emma-local",
  "scene_options": { "weather": "day", "scale": "standard" },
  "client_version": "0.1.0"
}
```

### 4.2 响应（服务器 → 客户端）
```json
{
  "scene_id": "scene-example-0001",
  "seed": "example-seed-0001",
  "generated_at": "2026-11-27T13:00:00+08:00",
  "manifest_url": "https://example.local/scene-example-0001/manifest.json",
  "assets": [
    { "path": "scene-assets/mesh.glb", "url": "", "sha256": "" }
  ],
  "spawn_point": {
    "position": [0.0, 0.0, 0.0],
    "rotation": [0.0, 0.0, 0.0]
  },
  "environment": { "lighting": "day", "background": "" },
  "checksum": ""
}
```

字段以实际服务为准；骨架只约束：种子、场景 ID、资源清单、出生点、校验和必须存在。

## 5. 离线与失败回退
- **场景服务关闭或不可达**：进入本地默认场景，或使用上次缓存场景；本地推理与 TTS 不受影响。
- **资源下载失败 / 哈希校验不通过**：丢弃该包，回退缓存或默认场景；不加载未校验的场景资源。
- **网络边界**：场景同步仅在用户进入场景、客户端开关启用时发起；对话文本、记忆不上传服务器。

## 6. 配置骨架
`modules/scene/scene-entry.example.json`：场景缓存目录、角色入场开关、默认出生点、服务器端点占位。实际端点写入 `runtime-config.json` 的 `scene` 段；仓库示例不写真实地址或密钥。

## 7. Smali / 工程对接要点
1. JADX 定位原版场景加载方法、角色出生 / 挂载方法、场景资源目录。
2. 入场前插入种子请求：子线程发起网络请求取清单，再下载资源；主线程只做场景渲染与角色放置。
3. 角色句柄 / 外观加载与场景加载解耦；场景切换不必重载对话模型，角色切换不必重载场景。
4. native 方法名、参数类型与 C 侧导出保持一致；网络调用、资源解析均在子线程。
5. 原版 Emma 模型、服装、场景贴图不得提取后对外分发；远端生成场景素材的使用许可需单独确认。
