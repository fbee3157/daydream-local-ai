# DayDream Companion — Quest 3 本机 llama.cpp 离线 AI 改造项目

> 定稿方案：**本机推理（Quest 3 端侧）**、引擎 **llama.cpp + GGUF**、**离线语音（STT / TTS）**、模型权重**自由导入**。项目同时保留云端接口作为可选扩展，但主链路为离线本地推理。本文汇总架构、目录、改造流程、GitHub 部署方式与合规边界。

## 一、定稿方案（已确认）

| 项 | 定稿选择 | 说明 |
|---|---|---|
| 推理位置 | Quest 3 本机端侧推理 | 不依赖 PC；离线可对话 |
| 推理引擎 | llama.cpp | GGUF 格式；NDK 编译为 arm64-v8a `.so` |
| 语音 | 离线 STT + 离线 TTS | 不调用云端语音服务；语音识别 / 合成在本机完成 |
| 模型权重 | 自由导入 GGUF | 权重外置到头显本地存储，不打入 APK；替换文件即可换模型 |
| 云端接口 | 可选保留 | 作为后续扩展；默认不启用，不影响离线主链路 |

### 1.1 合规与使用边界（必须遵守）
- 逆向修改、重打包、回装仅限**本人合法持有的原版副本**做个人研究。
- 修改后的安装包**不得上架商店、不得对外分发或二次发布**。
- **原版 APK、角色模型、服装、场景素材属于第三方版权，不得提交到公开 GitHub 仓库**；仓库只放自研代码、脚本、配置、文档与接入示例。
- Gemma、Qwen 等模型权重使用须遵守对应模型许可；对话输出保持健康合规。
- 对话与记忆默认只存本机本地目录，未经授权不上传外部服务。

## 二、运行环境

| 项目 | 说明 |
|---|---|
| 头显 | Meta Quest 3（骁龙 XR2+ Gen2，ARM64，8GB 共享内存，Android 底层） |
| 开发电脑 | MacBook（macOS，zsh） |
| 调试连接 | ADB（Android SDK Platform Tools） |
| 反编译工具 | Apktool、JADX |
| 原生编译 | Android NDK、CMake |
| 推理引擎 | llama.cpp + GGUF（NDK 交叉编译） |
| 离线语音 | 端侧 STT 识别库 + 端侧 TTS 合成库（离线运行） |

### 2.1 Quest 3 本机内存约束
- 4B 模型 Q4_K_M 权重约 2.5–3GB，运行内存约 3.0–3.4GB；应用纹理、离线语音、KV 缓存还需占用剩余内存。
- NPU 在第三方应用上驱动覆盖有限，实际多以 CPU / GPU 运行，不把 NPU 加速作为确定收益。
- 内存吃紧时处理顺序：降量化档位（Q3_K_M）→ 缩小上下文长度 → 减小模型规模。
- 离线 STT / TTS 模型与推理模型共享同一内存池，需一并计入预算。

### 3.1 本机推理链路
1. 启动后检查存储权限，校验外置 GGUF 权重与分词器是否存在。
2. JNI 调用 NDK 编译的 llama.cpp 原生库，加载权重与分词器，初始化上下文。
3. 用户输入（文字或离线 STT 识别结果）→ 组装提示词上下文 → 推理生成回复文本。
4. 回复交给对话 UI、离线 TTS 语音播放与口型触发；对话历史写入本地记忆目录。

### 3.2 离线语音链路
- **STT（语音识别）**：麦克风采集语音 → 端侧离线识别为文字 → 送入对话输入。不依赖云端语音服务。
- **TTS（语音合成）**：回复文本 → 端侧离线合成语音播放；文本同时接入口型动画触发点，复用原版已有动画事件。

### 3.3 云端接口定位（可选，默认关闭）
- 云端对话接口仅作为后续扩展项；离线主链路不发起云端推理请求。
- 原版云端后端是否仍在线，需解包检查网络配置或真机试聊确认；不把云端可用性作为运行前提。

## 五、改造阶段流程（操作手册）

### 阶段 1：提取原版安装包（Mac + ADB）
1. Quest 开启 USB 调试；Mac 校验设备：
```bash
adb devices
```
2. 定位包名：
```bash
adb shell pm list packages | grep -i dream
```
3. 查询 APK 路径并拉取基础包与分包：
```bash
adb shell pm path <包名>
mkdir -p ~/QuestApk && cd ~/QuestApk
adb pull <base.apk 路径> ./base.apk
# 对 split_config.*.apk 分包逐个 adb pull
```

### 阶段 2：反编译与代码定位
1. Apktool 解包：
```bash
apktool d base.apk -o daydream_decoded
```
2. JADX 打开原版 APK，定位：
   - 对话输入框与消息发送逻辑；
   - Emma 对话气泡、台词文本来源；
   - 语音录制、播放、口型动画触发点；
   - 网络请求层（云端对话接口、API 域名）；
   - `lib/` 下是否存在原生推理库，判断原版为云端还是本地推理。

### 阶段 3：llama.cpp 推理模块集成
- APK 内：NDK 编译 llama.cpp 产物放入 `lib/arm64-v8a/`；JNI 加载代码调用原生库。
- 外置：GGUF 权重、分词器、记忆文件放在头显本地存储，不打进 APK。
- 启动流程：检查存储权限 → 校验模型文件 → 加载权重与分词器 → 接收输入 → 推理生成 → 输出到对话 UI。
- **权重自由导入**：应用扫描外置模型目录，读取 GGUF 文件与配套分词器；更换模型只需替换目录内权重文件，无需改动 APK 代码。

### 阶段 4：离线语音与记忆模块
- **离线 STT**：端侧语音识别库把麦克风语音转为文字，送入对话输入。
- **离线 TTS**：回复文本端侧合成语音，并接入口型动画触发点；复用原版已有动画事件。
- **记忆**：短期会话历史 + 长期偏好 / 角色设定本地落盘；进阶使用向量检索回忆历史片段。
- **联网搜索（可选）**：判断检索需求 → 取资料摘要 → 拼入提示词上下文；离线环境下该模块可停用。

### 阶段 5：重打包、对齐、签名、回装
1. 回编译：
```bash
apktool b daydream_decoded -o daydream_modified.apk
```
2. 对齐：
```bash
zipalign -f -v 4 daydream_modified.apk daydream_aligned.apk
```
3. 签名（调试密钥库 + apksigner）：
```bash
apksigner sign --ks <密钥库> --ks-key-alias <别名> daydream_aligned.apk
```
4. 回装 Quest（分包应用按 split APK 安装方式处理）：
```bash
adb install -r daydream_aligned.apk
```

## 六、模型与引擎备忘

### 6.1 llama.cpp（定稿引擎）
- 模型格式：GGUF 单文件量化格式。
- 导入新模型成本最低：放入外置模型目录即可；无需格式转换。
- NDK 交叉编译目标：arm64-v8a（Quest 3 / XR2+ Gen2）。
- Gemma 3 4B、Qwen 4B 只要提供 GGUF 量化版即可接入。

### 6.2 其他框架（仅备查，本项目不采用）
| 框架 | 模型格式 | 备注 |
|---|---|---|
| MNN-LLM | MNN（需转换） | 移动端优化备选，非本项目选型 |
| ExecuTorch | PTE（PyTorch 导出） | PyTorch 链路优先，运行时体积小 |
| LiteRT-LM | LiteRT（需转换） | Google 端侧框架，Quest XR 需真机验证 |
| MLC-LLM | MLC 编译产物 | GPU 为主，无 NPU；不选作本机主力 |
| ONNX Runtime Mobile | ONNX | 框架中立，LLM 案例较少 |

### 6.3 模型内存记录（Quest 3，8GB 共享内存）
- Gemma 3 4B（`gemma-3-4b-it`）：Q4_K_M 约 2.49GB 权重、运行内存约 3.0–3.4GB；Q3_K_M 约 2.10GB；Q8_0 约 4.13GB。视觉投影 mmproj 约 851MB，纯文字对话不需要。
- Qwen 4B：优先 GGUF 量化版；内存预算与 Gemma 3 4B 同档。
- KV 缓存随上下文长度增长；短上下文优先。

## 八、关键风险清单

1. **签名校验**：重打包后签名变更，可能被客户端 / 系统校验拦截；仅限个人侧载研究。
2. **内存预算**：4B 模型 + 离线 STT/TTS + 记忆 + 应用纹理同时驻留偏紧；先真机验证内存占用。
3. **云端后端不确定性**：原版服务器若下线，云端链路不可用；本机离线推理不依赖该链路。
4. **版权素材**：角色与场景素材不得提取、再分发或二次修改发布。
5. **模型许可**：遵循 Gemma、Qwen 各自使用条款；生成内容合规。

## 九、术语对照

- **GGUF**：llama.cpp 使用的单文件量化模型格式。
- **NDK**：Android 原生开发工具包，用于编译 C/C++ `.so` 库。
- **JNI**：Java/Kotlin 与原生 C/C++ 代码互调用接口。
- **STT**：Speech-to-Text，语音识别（本项目离线运行）。
- **TTS**：Text-to-Speech，语音合成（本项目离线运行）。
- **KV 缓存**：推理过程中缓存注意力键值，占用常驻内存；上下文越长占用越高。
- **split APK**：应用分包，包含基础包与按架构 / 语言拆分的配置包。
